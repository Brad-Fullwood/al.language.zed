# Project Audit Backlog — 2026-07-31

A full-repository audit intended as an implementation backlog. Seven parallel subsystem audits
were run across the workspace; **every finding below was verified against the actual code**
(several were additionally reproduced by parsing real AL through the built grammar). The
baseline is healthy — `cargo clippy --workspace --all-targets` is clean and the full workspace
test suite passes (60/60 suites) — so nothing here comes from a broken build; these are latent
bugs, behavioral divergences from Business Central/AL semantics, gaps, and missing coverage.

**227 findings**: 123 BUG · 46 GAP · 17 PERF · 17 TEST · 24 DOCS.

Tags: **[BUG]** incorrect behavior with a concrete failure scenario · **[GAP]** missing or
incomplete functionality · **[PERF]** measurable performance problem · **[TEST]** missing
coverage that would have caught a listed bug · **[DOCS]** documentation contradicting shipped
behavior.

Each finding is self-contained (file:line + failure scenario) and sized to be picked up
independently by an implementation agent. Fixes for BUG entries should generally land with the
matching TEST entry from the same section.

## Start here — highest-impact items

1. **Object names invisible to Zed** — the grammar's `object_declaration` `name` field is never
   populated, killing outline/breadcrumbs, `@title` highlighting, and locals for every object
   (§ Syntax & Grammar, first four findings).
2. **File-corrupting code actions** — `add_parens` turns `end;` into `end();`, `if_to_case`
   deletes trailing code and the closing `;`, `with_elimination` rewrites identifiers inside
   string literals, "Move ToolTip" deletes the tooltip without moving it, and the promoted-action
   conversion emits invalid AL (§ Analysis & Insight). A shared "apply edit → re-parse → assert
   no ERROR nodes" test harness would pin all of these.
3. **Interpreter record semantics** — all record variables of a table share one filter set,
   cursor, and buffer; filter case-sensitivity is inverted vs BC (`@` prefix backwards);
   `Rec.Amount += 5` stores `5`; `Get`/`FindFirst` miss silently passes in statement position
   (§ Runtime & DAP).
4. **LSP responsiveness bugs** — a single global debounce slot cancels other files' pending
   diagnostics, and the generation read-lock is held across multi-second semantic-bridge calls,
   stalling typing for every open document (§ LSP & Protocol).
5. **Symbol index keyed by display name only** — two apps sharing a name silently evict each
   other; plus one corrupt `.app` (or one odd `.al` in a dependency) aborts the entire workspace
   initialization (§ Symbols & Project).
6. **XLIFF pipeline** — generated trans-unit IDs collide and do not match Microsoft's
   hash-based format (breaking the documented translation-memory compatibility), refresh output
   order is nondeterministic, and the user's `.xlf` is overwritten non-atomically
   (§ Emit, BC & Explorer).
7. **DAP correctness** — breakpoints set before `launch` are permanently dropped, stack frames
   are off by one line (0-based BC lines passed straight through), and every stop is reported
   as reason `"breakpoint"` (§ Runtime & DAP).
8. **Credential handling** — scheme-less on-prem servers get `http://` prepended and Basic
   credentials go out in cleartext; the tenant is sent as a header the BC dev endpoint ignores;
   `--password` is argv-visible with no env fallback; error-body secret redaction is
   case-sensitive (§ Emit, BC & Explorer).
9. **Extension startup offline** — a previously downloaded `al-lsp` is only reused after a
   successful GitHub release lookup, so offline starts fail despite a valid cached binary
   (§ Extension, CI & Docs).
10. **CLI exit codes** — every `debug`/`snapshot`/`profile` subcommand exits 0 even when the
    operation reports failure, breaking the documented CI gate contract
    (§ Emit, BC & Explorer).

## Cross-cutting themes (each is a sweep-sized work item)

- **AL case-insensitivity sweep** — case-sensitive comparisons on attribute names
  (`IntegrationEvent`/`EventSubscriber` in al-symbols, al-analysis, al-insight), `true/false`
  highlighting, date/time literal suffixes (`0d` vs `0D`), and filter matching. AL is
  case-insensitive everywhere; these should share one canonical comparison helper.
- **One-bad-file-fails-everything** — workspace init (corrupt `.app`), whole-workspace analysis
  snapshots (one unparsable `.al`), daemon/MCP startup (one oversized file), and dependency
  source indexing all abort wholesale instead of degrading per-file with a diagnostic.
- **Edit-application test harness** — no code-action test applies its generated edit and
  re-parses the result; that single harness would have caught at least six file-corruption bugs.
- **Atomic writes for user files** — `xlf refresh` (and any other user-file writer) should use
  temp-file + rename like `native_compile` already does.
- **Non-ASCII / UTF-16 coverage** — no al-lsp test pushes multi-byte content through position
  conversion; byte-vs-UTF-16 column confusion already exists in al-syntax token classification.
- **Unbounded caches** — the virtual-file cache and symbol disk cache grow forever; both need GC.
- **Blocking work on async executors** — several daemon/LSP handlers run workspace-scale walks
  inline where sibling handlers already use `spawn_blocking`; audit all dispatch paths.
- **Panic hardening** — ~2,400 `.unwrap()` calls concentrated in al-analysis (635), al-lsp (352),
  and al-symbols (315); prioritize paths reachable from client/network/package input.
- **Query & asset drift** — `languages/al/*.scm` vs `tree-sitter-al/queries/*.scm` have diverged
  despite docs claiming they are copies; the tree-sitter corpus has a single test file.

## Syntax & Grammar (al-syntax, tree-sitter-al)

Note: `tree-sitter-al/` is a git submodule that is not checked out by default in fresh clones; the audit had to initialize it manually — worth confirming CI/docs cover that.

- **[BUG]** `tree-sitter-al/grammar.js:260-292` — The `object_declaration` `name` field (`field('name', optional($.name_or_keyword))`, line 288) is **never populated**: the GLR conflict with `repeat($._pre_object_body)` (line 290, conflict declared at lines 219-220) always wins, so the object name parses as a bare inlined `(identifier)`/`(quoted_identifier)` child. Verified: `child_by_field_name("name")` returns `None` for `codeunit 50100 Test {}`. Every query that matches `name:` on `object_declaration` is dead (see next three findings).
- **[BUG]** `languages/al/outline.scm:5-7` (same in `tree-sitter-al/queries/outline.scm:4-6`) — `(object_declaration kind: (_) @context name: (_) @name) @item` never matches because the `name` field is never set (verified with `QueryCursor`), so **objects never appear in Zed's tree-sitter outline/breadcrumbs** — only procedures/triggers do.
- **[BUG]** `tree-sitter-al/queries/highlights.scm:230-231` — the two `@title` patterns for object names never match (same dead `name:` field, verified); unquoted object names fall back to plain `@variable`.
- **[GAP]** `tree-sitter-al/queries/locals.scm:36-40` — `(object_declaration name: (name_or_keyword …) @local.definition.type)` never matches for the same reason; object names produce no local definition.
- **[BUG]** `tree-sitter-al/src/scanner.c:544-577` — `scanner_scan_directive` interprets only `if/elif/else/endif`; in-source `#define`/`#undef` are consumed as generic DIRECTIVE tokens but never update the defines table (defines come only from the `AL_TS_DEFINES` env var, lines 282-311). Verified failure: `#define MYFLAG` followed by `#if MYFLAG` marks the guarded code as `(inactive_code)`, so valid active code is dimmed/excluded and unparsed.
- **[BUG]** `tree-sitter-al/grammar.js:1167-1169` — `date_literal`/`time_literal`/`datetime_literal` hardcode uppercase `'D'`/`'T'` suffixes, but AL is fully case-insensitive; verified `da := 20240131d;` and `da := 0d;` produce ERROR nodes while `0D` parses.
- **[BUG]** `tree-sitter-al/grammar.js:1172-1176` — `string` and `quoted_identifier` tokens match `[^']`/`[^"]` including newlines, but AL string/identifier literals are single-line; verified an unterminated `'oops);` swallows the rest of the procedure until the next quote and destroys the parse of the following procedure (ERROR spanning the whole object) — very poor error recovery for the most common typo in an editor.
- **[BUG]** `tree-sitter-al/grammar.js:188-195` + `crates/al-syntax/src/complexity.rs:91-98,152-166` — the external tokens `op_and/op_or/op_div/op_mod/op_xor/op_is/op_as` are never referenced by any grammar rule (only `op_not` is); `and`/`or` actually lex as `(binary_operator (operator_word))` (verified in s-expr). Consequently `complexity.rs`'s matching on `"op_and" | "op_or"` never fires: `if a and b or c then` yields cyclomatic 2 instead of 4, contradicting `Docs/features/parsing-and-syntax.md:80-82` ("Decision sources: … and/or operators").
- **[GAP]** `tree-sitter-al/queries/highlights.scm:70-77` — the `(op_and)`…`(op_xor)` capture patterns are dead for the same reason (those nodes are never produced except `op_not`); word operators are only covered by the generic `(operator_word)` rule at line 215.
- **[BUG]** `crates/al-syntax/src/tokens.rs:315-323` — `classify_node` returns `None` for `"directive"` claiming the DFS will classify its children, but `directive` is an external **leaf** token (verified `child_count == 0`), so `#if/#endif/#pragma/#region` lines emit **zero** semantic tokens; `PREPROCESSOR_KEYWORD` (index 23) is never produced.
- **[GAP]** `tree-sitter-al/queries/highlights.scm` — no capture at all for `(directive)`, `(inactive_code)`, `(time_literal)`, or `(datetime_literal)` (only `date_literal` at line 9), so preprocessor lines, excluded code, and time/datetime literals render unhighlighted in Zed.
- **[BUG]** `tree-sitter-al/queries/highlights.scm:15-16` — `(#match? @constant.builtin "^(true|false)$")` is case-sensitive, but AL accepts `TRUE`/`True`; those spellings highlight as plain variables.
- **[BUG]** `crates/al-syntax/src/tokens.rs:446-452` — `classify_name_like_node` matches parent kind `"field_declaration"`, a node that does not exist anywhere in the grammar (0 hits in `node-types.json`); the `TABLE_FIELD` token type (19) is unreachable through this path — dead branch, table field names never get their dedicated token.
- **[BUG]** `crates/al-syntax/src/tokens.rs:576-579` — `is_builtin_record_member` builds a `SyntaxPosition` from `member.start_position().column` (a **byte** column) but `TypeResolver::find_enclosing_procedure` (`type_resolver.rs:186-190`) treats `position.character` as UTF-16 and converts it to bytes; on lines containing non-ASCII, the receiver resolves at the wrong point and record-builtin highlighting silently misclassifies.
- **[PERF]** `crates/al-syntax/src/tokens.rs:539-583` + `crates/al-syntax/src/type_resolver.rs:119-177` — for every `member_call_suffix` whose member is a record method name, `extract_semantic_tokens` calls `resolve_type`, which re-runs `variables_at`: full procedure lookup via `source.lines().nth(row)` (O(file)), full global-var walk, and `collect_dataitem_vars`'s whole-file `windows()` scan — O(tokens × file-size) on large record-heavy files.
- **[BUG]** `crates/al-syntax/src/lint.rs:198-244` — `scan_procedure_for_find_in_loop` pushes a loop frame for `for … do` without `begin` (line 213-216) but nothing ever pops it (only `end`/`until` lines pop), so after a single-statement loop the whole rest of the procedure is "inside a loop". Verified: `for i := 1 to 3 do Foo(i);` followed later by `Rec2.FindFirst();` falsely raises AL-NL001 on the post-loop line.
- **[BUG]** `crates/al-syntax/src/symbols.rs:1155-1206` — `collect_label_symbols_from_text` is a raw text scan that does not strip comments; verified a commented-out `// MyLbl: Label 'disabled';` inside a var section produces a bogus outline symbol literally named `"// MyLbl"` with detail `Label`.

## Analysis & Insight (al-analysis, al-insight)

- **[BUG]** `crates/al-analysis/src/queries/code_actions/add_parens.rs:21-41` — the "bare call" heuristic accepts any word-only line ending in `;`, including keyword statements; placing the cursor on an `end;` or `break;` line offers "Add parentheses to method call" whose edit produces `end();`/`break();` and corrupts the file.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/if_to_case.rs:71-83` — the replacement range ends at `(if_end_row + 1, col 0)`, deleting any code after the if-statement on its last line, and the generated text ends with bare `end\n` so the statement's trailing `;` (which lives outside the `if_statement` node) is lost, yielding a syntax error when the case is not the last statement of a block.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/if_to_case.rs:57-68` — every branch body line is re-emitted as `body_indent + line.trim()`, flattening all relative indentation of nested `begin/end`/`if` structure inside branch bodies.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/with_elimination.rs:297-354` — `substitute_field_names` replaces field-name matches inside single-quoted string literals and trailing `//` comments (prev-char check only excludes `.`/`:`/ident chars), so `with Cust do Message('Name: %1', Name)` rewrites the `Name` inside the string literal to `Cust.Name`.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/with_elimination.rs:266-281` — the structural pass qualifies any line starting with `Ident(`, including calls to the object's own procedures, so `with Cust do begin Helper(); end` becomes `Cust.Helper();`, which does not compile.
- **[PERF]** `crates/al-analysis/src/queries/code_actions/with_elimination.rs:315-318` — `substitute_field_names` calls `remaining.to_lowercase()` on the whole line tail at every byte position for every field name, O(len² × field_count) per line.
- **[GAP]** `crates/al-analysis/src/queries/code_actions/with_elimination.rs:22-30` — field resolution uses only the first Table/TableExtension symbol entry whose *name* matches; fields contributed by tableextensions of that table are never in the field list and stay unqualified after the `with` is removed.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/implement_interface.rs:218-220` — `find_stub_insertion_line` returns the closing-brace row and the edit inserts at column 0 of that row; for a single-line object like `codeunit 50100 X { }` (end row = declaration row) the stubs are inserted *before* the entire declaration, producing invalid AL.
- **[GAP]** `crates/al-analysis/src/queries/code_actions/implement_interface.rs:43-64` — interface inheritance is ignored (only `iface_entry.methods` is stubbed, methods from a base interface via `extends` are never generated), and method/parameter names that require quoting are emitted unquoted.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/events.rs:72-91` — "Move ToolTip to table field" only deletes the page ToolTip line and never inserts anything into the table field, so applying the action silently destroys the tooltip text; code-actions.md line 24 documents it as actually moving the tooltip.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/events.rs:34-64` — the `in_page_field` backward scan matches any earlier `field(` line (the brace-depth counter is computed then discarded via `let _ = depth`), so a ToolTip inside a page *action* block also receives the delete-tooltip action.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/promoted.rs:220-225` — the generated `actionref({name}_Promoted; {name})` uses the unquoted action name, so `action("My Action")` yields invalid `actionref(My Action_Promoted; My Action)`; additionally each conversion inserts a fresh `area(Promoted)` block (duplicates on repeated use), `PromotedCategory` is mistranslated into `Caption = '<cat>'`, and `PromotedOnly`/`PromotedIsBig` lines are left orphaned.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/make_local.rs:84-94` — the already-local check is `line.contains("local ")`, so on an `internal procedure` the action is still offered and its edit produces `internal local procedure`, an invalid modifier combination; a comment containing "local " on the declaration line also falsely suppresses the action.
- **[BUG]** `crates/al-analysis/src/queries/code_actions/namespace.rs:147-197` — `try_extract_quoted_identifier` pairs a *closing* quote to the left of the cursor with the next quote to the right, so a cursor between two quoted identifiers (`... "X"; B: Record "Y"`) extracts garbage like `; B: Record ` as the word; `source_action_add_using` also triggers on words inside comments and string literals.
- **[DOCS]** `Docs/features/code-actions.md:30` vs `crates/al-analysis/src/queries/code_actions/doc_region.rs:111-125` — docs say "Wrap in region" emits `#region Name … #endregion`; the implementation emits `//region MyRegion` / `//endregion`, which is not AL's `#region` directive and won't fold as a region.
