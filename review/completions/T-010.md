## Validation
- Compilation: `cargo check -p al-test-harness` — PASS
- Notification failures are logged at warn level with the URI and error message
- Notifications are fire-and-forget in LSP, so logging and continuing is correct behavior
- stdin/stdout errors propagate via `?` since they're fatal to the client

## Justification
This is library code used by all E2E tests. A notification failure shouldn't crash the test process — it should be logged so the test can fail on an assertion instead, giving a better error message. The stdin/stdout errors are fatal (can't run without them) so propagating with `?` is appropriate.
