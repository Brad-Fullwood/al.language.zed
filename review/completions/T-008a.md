# T-008a: Fix DashMap deadlock in al-lsp workspace initialization

## Status: COMPLETED

## Task
DashMap `Ref` guard held across `.await` at line 230 of `crates/al-lsp/src/workspace.rs`. One-line fix to drop guard before any async operation.

## Changes Made
- **File:** `crates/al-lsp/src/workspace.rs`
- **Line 215:** Added `drop(text_entry);` after `let text = text_entry.value().clone();`
- This releases the DashMap shard lock before any subsequent `.await` points

## Validation
- Compilation: `cargo check -p al-lsp` — PASS
- Pattern matches CLAUDE.md guidance: "Clone data, drop ref, then await"
- The cloned `text` value is used for all subsequent operations — no need to hold the ref

## Justification
DashMap uses shard-level locks. Holding a `Ref` guard across an `.await` point means the shard lock is held while the task is suspended. If another task needs the same shard, it blocks, and if the blocked task holds a resource the first task needs, it deadlocks. This is a confirmed deadlock pattern documented in the project CLAUDE.md.
