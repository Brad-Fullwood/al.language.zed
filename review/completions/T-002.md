# T-002: Fix DAP `continue` command argument

## Status: COMPLETED

## Task
In `crates/al-dap-client/src/native_dap.rs`, `continue_execution(json!({}))` passes an empty object instead of the expected `BreakpointExitReason` integer. BC rejects the command silently.

## Changes Made
- **File:** `crates/al-dap-client/src/native_dap.rs`
- **Line ~704:** Changed `s.continue_execution(serde_json::json!({}))` to `s.continue_execution(serde_json::json!(0))`
- Added comment: `BreakpointExitReason = 0` means "continue" (resume execution). Values: 1=step over, 2=step in, 3=step out.

## Validation
- Compilation: `cargo check -p al-dap-client` — PASS
- The BC DAP adapter expects an integer representing BreakpointExitReason, not a ContinueArguments object
- Value 0 is the "continue" (resume) action

## Justification
BC's custom DAP implementation uses BreakpointExitReason integers for the continue command, not the standard DAP ContinueArguments. Passing an empty object caused BC to silently reject the command.
