# T-003: Fix DAP variables handler — decode frame+scope encoding

## Status: COMPLETED

## Task
The `scopes` handler encodes variablesReference as `frame_id * 100 + scope_index`, but the `variables` handler passes the raw value without decoding. This means variables requests go to the wrong scope.

## Changes Made
- **File:** `crates/al-dap-client/src/native_dap.rs`
- **Lines ~838-850:** Added decoding logic before dispatching:
  ```rust
  let frame_id = vars_ref / 100;
  let scope_index = vars_ref % 100;
  ```
- Routes `scope_index == 2` to `get_globals(frame_id)`, otherwise to `get_variables(frame_id)`

## Validation
- Compilation: `cargo check -p al-dap-client` — PASS
- Encoding matches the scopes handler pattern: `frame_id * 100 + scope_index`
- Scope index 1 = locals, scope index 2 = globals (matching BC DAP conventions)
- Decoded `frame_id` is now passed to the backend functions instead of the raw encoded value

## Justification
Without decoding, `get_variables` received the composite `frame_id * 100 + scope_index` value as a frame ID, which doesn't correspond to any real frame. This broke variable inspection in the debugger.
