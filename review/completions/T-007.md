# T-007: Fix al-explorer `details_items` rebuild location

## Status: COMPLETED

## Task
Move `details_items` rebuild from the render function to `update_objects_list()` to prevent stale data between draws.

## Changes Made
- **File:** `crates/al-explorer/src/main.rs`
- **Extracted** all details_items building logic into new `fn update_details_items(&mut self)` method (~250 lines)
- **Called from:** `update_objects_list()` and object navigation functions (`next_object`/`previous_object`)
- **Render function** now only reads from `self.details_items` to construct ListItem widgets — no rebuilding

## Validation
- Compilation: `cargo check -p al-explorer` — PASS
- Verified: all `details_items.push()` and `details_items.clear()` calls are only in the new `update_details_items()` method
- Render function only has `app.details_items.iter()` — read-only access
- Details pane updates whenever object selection changes, which is the correct behavior

## Justification
Building display data inside the render function meant: (1) stale data between draws if the selection changed without a full redraw, (2) inconsistent state for event handlers that reference `details_items`, and (3) unnecessary work on every frame.
