# T-008b: Fix DapClient::spawn expect panics

## Status: COMPLETED

## Task
Replace `expect("child stdin/stdout")` with proper error handling in `DapClient::spawn`, which is a public library function that returns `Result`.

## Changes Made
- **File:** `crates/al-dap-client/src/client.rs`
- **Lines 47-54:** Replaced:
  ```rust
  let stdin = child.stdin.take().expect("child stdin");
  let stdout = child.stdout.take().expect("child stdout");
  ```
  With:
  ```rust
  let stdin = child.stdin.take()
      .ok_or_else(|| DapError::SpawnFailed("child stdin not available".to_string()))?;
  let stdout = child.stdout.take()
      .ok_or_else(|| DapError::SpawnFailed("child stdout not available".to_string()))?;
  ```

## Validation
- Compilation: `cargo check -p al-dap-client` — PASS
- Uses the existing `DapError::SpawnFailed` variant — no new types needed
- Propagates error with `?` instead of panicking — callers already expect `Result`

## Justification
A public library function that returns `Result` should never panic on recoverable errors. `stdin/stdout` being unavailable is a configuration error (e.g., piped stdio not set up), not an invariant violation. Callers should be able to handle this gracefully.
