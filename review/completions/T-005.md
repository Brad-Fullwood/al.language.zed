# T-005: Fix al-cli `apply_workspace_edit` stale offset computation

## Status: COMPLETED

## Task
In `crates/al-cli/src/commands/lsp.rs`, byte offsets are computed from the original `lines` slice after `replace_range` mutates `new_content`, causing subsequent edit offsets to be wrong.

## Changes Made
- **File:** `crates/al-cli/src/commands/lsp.rs`
- **Lines ~985-1015:** Restructured the edit application:
  1. Edits are sorted descending by position (already existed)
  2. **NEW:** All byte ranges are pre-computed against the original `lines` before any mutation
  3. Mutations now iterate over pre-computed `(start_byte, end_byte, new_text)` tuples
  4. Bounds checking moved to the pre-computation phase
- The pre-computation + descending sort guarantees correctness: each replacement only affects positions above it in the file

## Validation
- Compilation: `cargo check -p al-cli` — PASS
- The fix preserves the existing descending sort, which is also important for correctness
- Error messages preserved with same format

## Justification
The original code called `lsp_pos_to_byte_offset(&lines, ...)` in each loop iteration, but `lines` was computed from the original content. After `replace_range` mutates `new_content`, the line boundaries change but `lines` still reflects the original state, causing all subsequent offset calculations to be wrong.
