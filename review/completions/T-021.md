# T-021: Move `configurationDone` to correct DAP lifecycle point
## Status: COMPLETED
## Changes
- File: `crates/al-dap-client/src/native_dap.rs`
- What: Moved the `configuration_done()` call out of the `launch` handler and into the `"configurationDone"` message handler so it fires after Zed has finished sending all initial breakpoints.
## Validation
- Compiles: YES
- Tests: PASS (943 tests, 1 pre-existing failure)
## Justification
Calling `configurationDone` during `launch` races with Zed's breakpoint-setting phase, causing BC to start execution before breakpoints are registered and silently skipping them.
