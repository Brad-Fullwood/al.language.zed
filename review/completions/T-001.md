# T-001: Fix DAP response field name `request_seq` → `requestSeq`

## Status: COMPLETED

## Task
In `crates/al-dap-client/src/native_dap.rs`, `make_response` uses snake_case `"request_seq"` instead of camelCase `"requestSeq"`, breaking all DAP response correlation with Zed.

## Changes Made
- **File:** `crates/al-dap-client/src/native_dap.rs`
- **Line ~963:** Changed `"request_seq": request_seq` to `"requestSeq": request_seq` in the `make_response` function's JSON object construction.

## Validation
- Compilation: `cargo check -p al-dap-client` — PASS
- Change is a single key name fix in a JSON literal — minimal risk
- The DAP protocol specification requires camelCase field names
- All other fields in the same JSON object (`seq`, `type`, `success`, `command`) are already camelCase

## Justification
The DAP specification uses camelCase for all field names. `requestSeq` is the standard field that correlates responses to requests. Using snake_case caused Zed to be unable to match responses to the requests that triggered them.
