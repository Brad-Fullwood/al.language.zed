# Brief Schema (coordinator → each reviewer)

Every Phase 2 / Phase 3 reviewer receives one brief at
`.agentic/<run-id>/review/briefs/<reviewer-name>.md`. Briefs are
generated by `review-coordinator` in Phase 1.

## Required frontmatter

```yaml
---
reviewer: <agent-name>
run_id: <run-id>
scope_files: [ "crates/al-core/src/queries/*.rs", ... ]
scope_crates: [ "al-core" ]
categories_owned: [ "bug", "code-quality", ... ]
non_overlap:
  - review-worker-core-infra owns al-core outside queries/
  - review-spec-security owns OAuth and .app extraction
estimated_tokens: 160000
output_path: .agentic/<run-id>/review/findings/<reviewer-name>.jsonl
---
```

## Required body sections (in order)

```markdown
# Brief for <reviewer-name>

## Assignment

One paragraph describing what this reviewer owns. Uses plain language;
no ceremony.

## Scope (exact file list)

Explicit file paths (not globs resolved at read-time) so there's no
ambiguity. Coordinator computes this in Phase 0/1:

- crates/al-core/src/queries/completions.rs
- crates/al-core/src/queries/hover.rs
- ...

If diff mode: only the files in `manifest.changed_files` intersected
with the reviewer's natural scope.

## Categories owned

Bullet list of the ultrareview categories this reviewer must cover.
Short phrase per category, not a description.

## Cross-cutting concerns (inlined)

Full contents of `.claude/docs/review/cross-cutting-concerns.md`
inlined here — the reviewer gets everything it needs without
re-reading the doc.

## Do NOT

Explicit bulleted list:
- Do NOT review code in other crates even if it looks related.
- Do NOT propose refactors (that's `review-spec-refactor`'s job).
- Do NOT write findings without a `file:line` citation.
- Do NOT mark `verdict` or `confidence` — that's the validator's job.
- Do NOT edit any source file.

## Output

Write one JSONL line per candidate finding to `<output_path>`.
Follow the schema at [../agentic/schemas/finding.md](../agentic/schemas/finding.md).

Return a summary reply with:
- total findings written
- count by severity
- count by kind
- anything you could not assess (e.g. "submodule bare, grammar unchecked")
- ≤ 800 tokens

## Stopping condition

When every file in scope has been read AND every owned category has
been considered for every file. No other stopping condition (not
"looks good enough" — this is over-report mode).
```

## Brief length guideline

Target: 3000–6000 tokens per brief. The cross-cutting concerns block
dominates; the scope list is usually short; the do-not list is short.
A 10K-token brief means the coordinator is padding — cut it.
