### [R7-SEC-1] one launch entry the strict parser rejects empties the trust record's server list, and the debug adapter then accepts any server
- where: crates/al-project/src/trust.rs:1205-1208 (`launch_privileges` returns nothing when `find_launch_config` fails), crates/al-bc/src/launch.rs:336-346 and :430-439 (one entry with `environmentType` other than exactly `OnPrem`, `Sandbox` or `Production`, or `authentication` other than the exact spellings, fails the whole file), against crates/al-project/src/trust.rs:937 (`BcTarget::from_debug` reads `OnPrem` case-insensitively) and crates/al-dap/src/dap/bc_debug/session_config.rs:366-373 and :441 (`validate_native` and `base_url` accept `onprem`)
- severity: medium
- scenario: a project that targets a cloud sandbox is trusted for its analyzer settings. Its record holds no on-premises server. A later commit adds `.zed/debug.json` with one scenario `{"adapter":"al","request":"attach","environmentType":"onprem","server":"https://collector.example","serverInstance":"BC","authentication":"AAD","tenant":"organizations"}`. `parse_environment_type("onprem")` is an error, so `find_launch_config` returns `Err` and `launch_privileges` returns an empty list. ### [R7-SEC-5] the trust record hashes the named file, and the code that file loads from beside it can still change under the record
- where: crates/al-project/src/trust.rs:663-683 (`with_project_contents` hashes one file for a file path), :366-392 (`project_analyzer_copies` hashes the one resolved DLL), against the .NET loaders: `Assembly.LoadFrom` in crates/al-semantic/bridge/Bridge.cs:744 resolves an analyzer's references from the analyzer's own directory, and a `dotnet` muxer loads `host/fxr/<version>/libhostfxr` and `shared/Microsoft.NETCore.App/<version>/` from the directory it sits in

- scenario: two shapes of the round 4 scenario that b39fff3b does not cover. (1) A trusted repository sets `"al.codeAnalyzers": ["./tools/TeamCop.dll"]` and ships `tools/TeamCop.Rules.dll`, which `TeamCop.dll` references. The record holds the SHA-256 of `TeamCop.dll` only. A later commit replaces `tools/TeamCop.Rules.dll`. The digest is unchanged, the record stays `trusted`, and the next build or semantic pass loads the new dependency. ### [R7-SEC-7] a revoke that lands while a settings change is in flight is lost in the language server
- where: crates/al-lsp/src/server/lsp/mod.rs:848 (`gate_repository_settings` stores `GATED_TRUST_INPUTS` when it gates, not when the gated configuration is installed), :1563 (`did_change_configuration` gates a staged copy), :1599, :1626, :1701 (the staged copy is installed later), :796-816 (`refresh_trust` returns early when the stored fingerprint matches)
- severity: low
- scenario: the project is trusted. Zed sends `didChangeConfiguration`. The handler gates `staged_config` while the project is still trusted, so the repository's analyzer stays in it, and stores the fingerprint F1. It then waits: on the advisory `show_message`, on the generation write guard, or, when a symbol path changed, on the package staging in `spawn_blocking`, which can take seconds. The user runs `al-explorer trust --revoke`. A build command arrives, `refresh_trust` sees the fingerprint move to F2, gates the live configuration (the old one) and stores F2. The settings handler then installs `staged_config`, which was gated at F1 and still holds the repository's analyzer. The stored fingerprint is F2, which matches the files, so every later `refresh_trust` returns at once. The build and the semantic pass keep loading the analyzer the user withdrew until the next settings change or restart. 06d1b41f promises that a revoke reaches a running language server. This is a check-then-act window between the gate and the install.
- fix: gate the staged configuration again under the same guards that install it (the gate is synchronous now), or store the fingerprint only when the gated configuration is installed. A test can hold the generation write guard, revoke, run a command's `refresh_trust`, release the guard and check the analyzer is gone.
- status: open
