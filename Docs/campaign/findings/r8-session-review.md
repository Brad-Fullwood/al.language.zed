## Findings

### [R8-RT-1] OnRename runs before the key changes, so its `Rec` holds the old key, and the rename events get the new key as `xRec`
- where: crates/al-runtime/src/interpreter/records.rs:922-948 (`OnRename` runs through `run_table_code` on the caller's buffer before `run_record_method` applies the new key at :1130-1150), :1006-1029 (`raise_table_event` passes the same record as `Rec` and `xRec`), crates/al-runtime/src/mock/record.rs:573-607 (`rename_in` writes the new key into the buffer only after the trigger ran)
- severity: high
- scenario: a workspace table "Member" with `trigger OnRename() begin if StrLen("No.") < 3 then Error('too short'); end;` and a test that inserts `LONGKEY` and calls `Member.Rename('AB')`. In Business Central `Rec` in OnRename holds the new key and `xRec` the old one (the base app's Customer.OnRename calls `DimMgt.RenameDefaultDim(Database::Customer, xRec."No.", "No.")`), so BC raises `too short` and the test is red. The router classifies the test `InterpRecord` (checked with a scratch router test: a table with an OnRename trigger and no globals, `Renames` routes `InterpRecord`), and locally `"No."` is still `LONGKEY`, so the check passes and the test is green. The reverse also happens: an OnRename that moves child rows from `xRec."No."` to `"No."` does nothing locally. An `OnAfterRenameEvent` subscriber gets `xRec` equal to `Rec` (both the new key), so a subscriber that renames related rows from `xRec` does nothing. Confirmed with a scratch test in records_tests.rs: an OnRename that errors when `"No." = xRec."No."` failed with `OnRename: Rec holds OLD and xRec holds OLD`, and an `OnAfterRenameEvent` subscriber that errors when `Rec."Entry No." = xRec."Entry No."` failed with the new key 2 in both. The commit's test (`textbuilder_guids_rename_and_testfield_run_locally`) uses a table with no OnRename and no subscriber.
- fix: in the rename path, coerce the new key, write it into a copy of the buffer, run OnBeforeRenameEvent and OnRename with that copy as `Rec` and the stored row as `xRec`, then call `rename_in`, and pass the stored old row as `xRec` to OnAfterRenameEvent. Add a test with an OnRename that reads both keys.
- status: open

### [R8-RT-2] `Rename` does not update the fields that relate to the renamed key, which Business Central does
- where: crates/al-runtime/src/mock/record.rs:573-607 (`rename_in` moves one row), crates/al-runtime/src/interpreter/records.rs:1130-1150, crates/al-test/src/router/ast.rs (Rename is a supported record method with no check for related tables)
- severity: medium
- scenario: the Record.Rename documentation says renaming "changes the primary key and updates the primary key value in all related tables" (learn.microsoft.com, record-rename-method, Remarks), and the OnRename trigger page says "When you rename a record in one location, it is updated in all other locations". The review brief states that Rename cascades nothing. The documentation says otherwise. Workspace tables `Plain` (key `No.`) and `Plain Entry` with `field(2; "Plain No."; Code[20]) { TableRelation = "Plain"; }`. A test inserts `Plain` `OLD` and an entry pointing at `OLD`, renames `Plain` to `NEW` and reads the entry. BC returns `NEW`. The local runtime returns `OLD` (confirmed with a scratch test: `RenameCascades => Normal(Code("OLD"))`). The router sends the test to the interpreter. A test that asserts the entry follows the rename fails locally and passes on BC. Code under test that looks up children by the old key after a rename finds them locally and not on BC, which can turn a red BC test green locally.
- fix: after `rename_in`, update every workspace table field whose plain `TableRelation` targets the renamed table (and field, when named) from the old key value to the new one. Until that exists, have the router send a test that renames a table some other workspace table relates to, to live BC.
- status: open

### [R8-ROUTE-1] the router does not reach the table event subscribers that `Rename` and record calls inside table code raise, which the interpreter now runs
- where: crates/al-insight/src/calls/mod.rs:143-151 and crates/al-insight/src/calls/edges.rs:333-346 (`RecordOp` has Insert, Modify, Delete and Validate, no Rename), crates/al-insight/src/calls/edges.rs:216-220 (a record call on a variable with no declared record type, such as the implicit `Rec` or a bare `Modify()` in table code, adds no edge), against crates/al-runtime/src/interpreter/records.rs:897-918 and :987-999 (every Insert, Modify, Delete and Rename raises OnBefore and OnAfter events, including those made from table code)
- severity: medium
- scenario: f81de5d6 made the interpreter run table event subscribers and routes tables with triggers locally, and relies on the call graph to classify the subscribers. Two shapes miss them. (1) A subscriber `[EventSubscriber(ObjectType::Table, Database::"Plain", 'OnAfterRenameEvent', '', false, false)]` that calls `Page.RunModal(0)`, and a test that calls `P.Rename('B')`: the router answers `InterpRecord` with no reason naming the subscriber. The same subscriber on `OnAfterModifyEvent` with a test that calls `P.Modify()` answers `LiveBc` ("reachable procedure calls Page.RunModal"). (2) A field `OnValidate` that runs `Rec.Modify()`, an `OnAfterModifyEvent` subscriber that calls `Page.RunModal(0)`, and a test that calls `P.Validate(Name, 'x')`: `InterpRecord`. Both confirmed with scratch router tests. The interpreter then runs the subscriber and the test fails locally with an error from `Page.RunModal`, where BC passes. A subscriber in a codeunit with globals fails the same way with "stateful codeunit requires live BC execution". Any other unsupported call in such a subscriber is only found at run time.
- fix: add `Rename` to `RecordOp` (OnBeforeRenameEvent and OnAfterRenameEvent), and in table code treat `Rec`, `xRec` and a bare record method as record calls on the table itself when the call graph records call sites. A router test for each shape.
- status: open

### [R8-ROUTE-2] a table or helper codeunit whose only globals are labels is treated as stateful and sent to live BC
- where: crates/al-test/src/router/mod.rs:740-757 (`has_object_global_declarations` counts any child of the object `var` section, so a `Label` counts), :519-537 (the "has object-level state" rule, which now also fires for tables), crates/al-runtime/src/interpreter/dispatch/workspace_procedure.rs:89-95 and :451-469 (`object_has_global_declarations` counts a label, and a helper codeunit with one is refused at depth above zero)
- severity: medium
- scenario: CodeCop AA0074 asks for error texts as labels, and a table usually keeps them as globals: `var NoRequiredErr: Label 'No. is required'; trigger OnInsert() begin if "No." = '' then Error(NoRequiredErr); end;`. A test that calls `L.Insert(true)` on that table routes `LiveBc` with the reason "reachable helper codeunit 'R8 Labelled' has object-level state that requires live BC execution" (the reason also calls a table a codeunit). The interpreter would run it: table code installs a fresh globals frame for each call and 901586e2 binds labels to their text. A helper codeunit with only `HelloLbl: Label 'Hello %1'` and a procedure that returns `StrSubstNo(HelloLbl, Name)` routes `LiveBc` for the same reason, and the interpreter refuses it with "stateful codeunit 'R8 Label Helper' requires live BC execution". Both confirmed with scratch tests. A label is a constant, so neither object has state. This sends most tables with triggers back to live BC, which f81de5d6 meant to stop.
- fix: count only `regular_variable_declaration` children (not `label_declaration`) in both `has_object_global_declarations` and `object_has_global_declarations`, bind label globals for a helper codeunit without refusing it, and name the object kind in the router's reason.
- status: open

### [R8-RT-3] a subscriber that takes `sender` fails locally, and the router keeps the test local
- where: crates/al-runtime/src/interpreter/dispatch/workspace_procedure.rs:399-445 (`raise_published_event` passes the publisher's parameter names only), crates/al-runtime/src/interpreter/dispatch/events.rs:164-176 (a subscriber parameter the event does not publish is an error)
- severity: medium
- scenario: a publisher `[IntegrationEvent(true, false)] local procedure OnPost()` (IncludeSender = true) and a subscriber `local procedure OnPostSub(sender: Codeunit "R8 Pub")`, the documented way to reach the publisher's instance. A test that calls `Pub.Post()` routes `Interp` with no reasons, and the local run fails with "subscriber R8 Sender Sub.OnPostSub declares parameter 'sender', which event OnPost does not publish". BC passes. Both confirmed with scratch tests. The same applies to a table event subscriber that declares `Sender`, which some code uses on page events.
- fix: when the publisher's attribute has IncludeSender set, pass the publishing object as `sender` (a codeunit value for a codeunit, the record for a table procedure), or have the router send a test that reaches such a subscriber to live BC until it is modelled.
- status: open
