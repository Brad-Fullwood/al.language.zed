# Benchmark findings — current correctness evidence

This document publishes no performance ratios. The current measurement is a
correctness run using release binaries and the installed Microsoft AL extension;
older timing and accuracy observations are superseded. The runs below were made
from a dirty completion worktree, so their timing samples remain provisional
even though their fail-closed correctness contracts passed. A clean-commit rerun
is required before publishing ratios.

## Planted-defect detection

The harness scores an error or warning only when it is in the intended file and
within ±2 lines of the planted defect. Each defect has its own project so parse
failures cannot suppress later cases. The clean control uses `SetLoadFields`
before its record read; this makes it a valid false-positive control for both
the LSP native-lint configuration and the production verifier.

| Defect class | n | `alc` | LSP | native build | `nativeCheck` | combined local |
|---|--:|--:|--:|--:|--:|--:|
| syntax | 3 | 3 | 3 | 3 | 0 | 3 |
| binding / name resolution | 5 | 5 | 0 | 5 | 0 | 5 |
| type checking | 4 | 3 | 0 | 4 | 0 | 4 |
| project rules | 2 | 2 | 1 | 2 | 2 | 2 |
| **total** | **14** | **13** | **4** | **14** | **2** | **14** |
| false positive on clean control | | none | none | none | none | none |

`native build` is `al-explorer pack-native --json`: it exercises the current
production native verifier used by native builds, not merely the advisory
`nativeCheck` query. In this run it catches every planted case: the three
syntax/property cases; undeclared names, unknown Record subtypes, package-backed
fields, local procedures and Record methods; Record-to-Integer assignment,
local argument count/type, and the elementary missing-return form; plus both
project rules. The malformed `DataClassification…` property diagnostic is
reported at its source line, so it satisfies the same ±2-line rule as the
other cases.

The result does not prove complete AL semantic compatibility. The verifier is
deliberately conservative outside the checked forms (for example, it does not
claim general expression typing or complete path-sensitive return analysis),
and it continues to leave non-literal return expressions unknown rather than
inventing a type error. `alc` also does not report the planted missing-return
case in this corpus.

The full machine-readable result is `results/accuracy.json`, regenerated by:

```bash
AL_BENCH_PACKAGES=/path/to/an/immutable/coherent/package-set \
  python3 benchmarks/scripts/gen_accuracy_corpus.py
AL_MS_EXT=/path/to/ms-dynamics-smb.al-17.0.2273547 \
  python3 benchmarks/scripts/accuracy_bench.py
```

## Package and performance evidence

No comparative timing result is published yet. The provisional six-round emit
matrix did, however, pass its correctness gate for small, medium, large, and XL
generated projects: all 60 measured native/`alc` pairs (plus 12 discarded
warmup pairs) built successfully and were semantically equivalent across
process-cold, warm-unchanged, and one-file-edit states.

The first matrix run correctly failed medium through XL because repeated `alc`
builds emit sibling `ActionDefinition` elements in different orders. The
comparator now parses navigation XML and normalizes only random `ControlGUID`
values and that proven Microsoft discovery-order nondeterminism. It retains
every action attribute and all non-action ordering as significant; dedicated
tests prove content changes still fail comparison.

The strict `make microsoft-contracts` profile also passed against this
Microsoft extension with a coherent BC 28.1 cache. That profile includes the
self-contained 19-object-kind differential, dependency and Base Application
bindings/resources, both `pack-native --validate` contracts, the live semantic
bridge, and receiver-sensitive built-in language services.

These results cover the declared fixture archive, manifest,
`SymbolReference.json`, XLIFF, navigation, logo, layout, and resource contracts.
They are not a claim of general package or Business Central runtime parity.
